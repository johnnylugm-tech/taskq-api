## Functional Requirement Test Cases

> Each FR section below follows the **8-Question Protocol** (Q1 happy path,
> Q2 validation, Q3 boundary, Q4 state transition, Q5 fault injection,
> Q6 NFR pattern, Q7 integration, Q8 deferred). Every case has a concrete
> `Inputs` value in true form (key="value"), NOT the pytest-id underscore form.
> Sub-assertion predicates are valid Python-expression syntax; the LHS
> identifier is never a Python stdlib top-level module name (`json`, `os`,
> `sys`, `time`, `subprocess`, `pathlib`, `asyncio`, `typing`, `logging`,
> `path`, `file`, `id`, `type`, `dict`, `list`, `set`, `tuple`, `str`, `int`,
> `bool`, `bytes`) — domain synonyms used where the prose would name such a
> word (e.g. `hash_value` instead of `hash`, `error_body_str` instead of
> `body`).
